# Личная доска вопросов — план реализации

> **Для исполнителя:** выполнять план по задачам; каждая задача должна иметь проверяемый результат. Для реализации использовать `superpowers:subagent-driven-development` либо `superpowers:executing-plans` согласно выбранному пользователем способу.

**Цель:** создать простую адаптивную одностраничную доску вопросов с входом Supabase и облачной синхронизацией личных записей.

**Архитектура:** статическая страница на HTML/CSS/JavaScript без сборщика. Supabase Auth управляет входом; одна таблица хранит вопросы; RLS ограничивает строки владельцем. Код разделён на UI, auth и запросы данных без избыточных слоёв.

**Технологии:** HTML, CSS, JavaScript ES modules, Node.js built-in test runner, Supabase JS major v2 через CDN (точный patch-релиз проверить и зафиксировать при реализации).

**Спецификация:** `docs/superpowers/specs/2026-11-26-question-board-design.md`

## Общие ограничения

- Без UI-фреймворка, сборщика и платных сервисов.
- Только одна персональная доска; совместный доступ, приглашения, публичные ссылки и роли не реализовывать.
- Вопрос содержит обязательный текст, необязательные `note` и `tag`, статус `open` или `completed`, `created_at` и `updated_at`.
- На экране статусы называются «В процессе» и «Завершено».
- Регистрация не требует подтверждения email; сброс пароля отправляет ссылку на email.
- В клиенте допустим только Supabase URL и публичный anon/publishable key. Никогда не использовать `service_role` key в браузере.
- Включить RLS: пользователь может читать и изменять только записи, где `user_id = auth.uid()`.
- Не добавлять удаление, перетаскивание, поиск, отдельную историю комментариев или совместную работу.
- Не публиковать сайт и не настраивать внешние аккаунты без отдельного подтверждения.

## Особое внимание при проверке

1. Пустой или состоящий из пробелов вопрос не сохраняется; поле получает понятную ошибку.
2. HTML/JS в вопросе, заметке или метке отображается как обычный текст и не исполняется.
3. Слишком длинный текст отклоняется до отправки; лимит показан рядом с полем.
4. Ошибка сети при загрузке/сохранении показывает понятное сообщение и не стирает введённые данные.
5. Другой пользователь не может прочитать или изменить чужую запись; RLS проверяется двумя тестовыми аккаунтами.

### Task 1: Статическая основа, конфигурация и проверяемая логика формы

**Файлы:**
- Создать: `index.html` — семантический каркас страницы и подключение ES-модуля.
- Создать: `styles.css` — адаптивные стили.
- Создать: `package.json` — только `type: module` и скрипт `test` на `node --test`, без зависимостей.
- Создать: `.gitignore` — исключить локальную конфигурацию `supabase-config.js`.
- Создать: `supabase-config.example.js` — пустые значения публичных URL/key и инструкция скопировать файл в локальный `supabase-config.js`.
- Создать: `src/app.js` — начальная точка приложения; пока отображает базовый экран.
- Создать: `src/validation.js` — проверка текста вопроса и ограничений длины.
- Создать: `test/validation.test.js` — проверки входных значений.
- В `index.html` подключить `supabase-config.js` перед модулем приложения; README объясняет копирование `supabase-config.example.js` в этот локальный файл.

**Интерфейсы:**
- `validateQuestion(input)` принимает `{ text, note, tag }`; возвращает `null` при успехе или объект с ошибками по полям.
- Начальные лимиты: вопрос — 500 символов, заметка — 2000, метка — 40. Вывести их у соответствующих полей.

### Task 3: Создание, список, редактирование и смена статуса

**Файлы:**
- Создать: `src/questions.js` — запросы к таблице `questions`.
- Создать: `src/render.js` — отображение доски/карточек через DOM API; пользовательские строки не вставлять через `innerHTML`.
- Изменить: `src/app.js` — связать действия интерфейса, авторизацию и запросы данных.
- Изменить: `index.html`, `styles.css` — форма карточки и две колонки.

**Интерфейсы:**
- `listQuestions()` → `Promise<Question[]>`, сортировка по `created_at` по убыванию.
- `createQuestion(input)` и `updateQuestion(id, input)` → `Promise<Question>`; `user_id` берётся из текущей сессии, не из формы.
- `setQuestionStatus(id, status)` принимает только `open | completed` и возвращает обновлённую запись.
- `renderBoard(root, questions, handlers)` отображает две колонки «В процессе»/«Завершено»; обработчики получают `id` записи и новые значения.
