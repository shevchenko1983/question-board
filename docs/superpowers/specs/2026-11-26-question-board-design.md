# Дизайн: личная доска вопросов

**Дата:** 2026-11-26
**Статус:** утверждено пользователем; совместная доска исключена.

## Зачем

Andrey хочет симпатичную одностраничную доску, куда можно складывать вопросы для обсуждения с преподавателем или онлайн, возвращаться к ним с разных устройств и не терять их со временем.

## Подходы

1. **Supabase Auth + база Supabase — выбранный вариант.** Один сервис даёт вход по почте и паролю и облачное хранение; подходит для личного списка и не требует собственного сервера.
2. **Firebase Authentication + Firestore.** Тоже рабочий облачный вариант, но для этой задачи не даёт заметного упрощения по сравнению с Supabase.
3. **Хранение только в браузере.** Самое простое, но не синхронизирует данные между устройствами — требование пользователя не выполняет.

Выбран Supabase: минимум отдельных частей при облачном входе и хранении. Бесплатный тариф зависит от актуальных условий Supabase и не считается гарантированно бесплатным навсегда.

## Цели первой версии

- Одна адаптивная страница с личной доской вопросов в визуальном духе Trello.
- Регистрация и вход по email и паролю без обязательного подтверждения email; сброс забытого пароля доступен по ссылке из письма.
- После входа пользователь видит свои вопросы с любого устройства.
- Создание и редактирование вопроса, одной заметки/комментария и одной необязательной метки.
- Два статуса: «В процессе» и «Завершено»; карточки показаны в соответствующих колонках.
- Сохранение в облачную базу Supabase.

## Не входит в первую версию

- Совместная доска, приглашения преподавателя, роли и публичные ссылки.
- Несколько комментариев/обсуждений к вопросу, вложения, уведомления, поиск, сортировка и статистика.
- Перетаскивание карточек между колонками: статус меняется простым действием на карточке.
- Удаление вопроса, чтобы не добавлять необратимую операцию без явной потребности.
- Публикация сайта или настройка облачных аккаунтов от имени пользователя.

## Модель данных и связи

Одна таблица `questions`:

- `id`: UUID, первичный ключ.
- `user_id`: UUID пользователя Supabase Auth, владелец записи.
- `text`: текст вопроса, обязательный.
- `note`: необязательный текст заметки/комментария.
- `tag`: одна необязательная текстовая метка.
- `status`: `open` или `completed`.
- `created_at`, `updated_at`: даты создания и последнего изменения.

Связь: один пользователь → много вопросов. Отдельные таблицы для заметок и меток не нужны в этой версии.

## Технология и границы

- Клиент: обычные HTML, CSS и JavaScript без фреймворка и сборщика — проект сейчас пустой, а объём приложения небольшой.
- Авторизация и база: Supabase, клиентская библиотека `@supabase/supabase-js` версии major `2`, подключённая как ES-модуль с CDN. Точный patch-релиз фиксируется при реализации по доступной версии пакета, чтобы не выдумывать номер.
- Хостинг статических файлов нужен для доступа к странице с разных устройств; публикация и выбор хостинга остаются отдельным шагом, не выполняются без согласования.

## Модули

- **Авторизация:** регистрация без подтверждения email, вход, выход, восстановление сессии и отправка ссылки для сброса пароля.
- **Данные:** загрузка и сохранение вопросов через Supabase; не содержит разметку интерфейса.
- **Интерфейс:** форма и карточки; показывает состояние данных и отправляет действия модулю данных.
- Для такого небольшого приложения это границы ответственности, а не отдельные сложные слои или классы.

## Основной сценарий

1. Пользователь открывает страницу и видит форму входа или доску, если уже вошёл.
2. Создаёт вопрос, при желании добавляет заметку и метку.
3. Вопрос появляется в колонке «В процессе».
4. Позже открывает сайт на другом устройстве, входит в ту же учётную запись, редактирует карточку или отмечает её «Завершено».

## UX и состояния

- **Пустая доска:** короткое объяснение и заметная кнопка добавления первого вопроса.
- **Загрузка:** понятная надпись/индикатор, чтобы не выглядело как зависшая страница; на время запроса кнопка блокируется от повторного нажатия.
- **Вход и регистрация:** простая форма email/пароль, переключение между входом и регистрацией и ссылка «Забыли пароль?»; подтверждение email не требуется. После отправки сброса показать понятное сообщение о проверке почты.
- **Успех:** доска с двумя колонками; действия подтверждаются видимым сообщением «Сохранено» или немедленным обновлением статуса.
- **Ошибка сети/сервера:** человеческое сообщение, введённый текст не теряется, есть действие «Повторить».
- **Валидация:** вопрос не может быть пустым; ограничение длины показывается у поля до сохранения.
- **Мобильный экран:** колонки располагаются одна под другой, основные кнопки удобны для нажатия пальцем; все действия доступны без hover.
- Поля имеют видимые подписи, формы доступны с клавиатуры.

## Безопасность и приватность

- Включить Supabase Row Level Security (RLS) для `questions`; правила чтения, добавления и изменения ограничивают строки текущим `auth.uid() = user_id`.
- В браузере разрешены только Supabase URL и публичный publishable/anon key при включённом и проверенном RLS. `service_role` key и пароль базы никогда не попадают в клиентский код.
- Пароли обрабатывает Supabase Auth; приложение не сохраняет их самостоятельно.
- Ввод ограничивается разумной длиной; текст карточек выводится как текст, а не вставляется в HTML, чтобы введённый код не исполнялся.
- Не сохранять вопросы в логи. Не отправлять записи посторонним.

## Критерии готовности

- Можно зарегистрироваться без подтверждения email, войти, выйти и запросить сброс пароля по email.
- Созданный вопрос, заметка, метка и статус сохраняются после перезагрузки и доступны после входа с другого устройства.
- Редактирование меняет запись в облаке; пользователь не может получить записи другой учётной записи.
- Пустое поле вопроса не сохраняется; состояния загрузки и ошибки видны.
- На узком экране форма и карточки остаются читаемыми и управляемыми.
- Проект содержит инструкцию по созданию Supabase-проекта, таблицы/RLS и настройке публичных клиентских значений; секретный ключ не требуется.

## Открытое эксплуатационное ограничение

Чтобы реально пользоваться страницей с разных устройств, статические файлы нужно будет разместить на хостинге, а Supabase-проект настроить в аккаунте пользователя. Это не входит в автоматическую публикацию: перед внешним развёртыванием потребуется отдельное подтверждение.
